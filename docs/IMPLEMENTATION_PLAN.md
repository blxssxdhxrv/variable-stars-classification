# Инструкция ИИ-агенту: классификация переменных звёзд по серии изображений

## 1. Задача и границы

Разработать локальное настольное приложение для учебного проекта по распознаванию образов. Основной вход — последовательность научных изображений FITS. Программа обнаруживает источники, позволяет выбрать звезду, сопоставляет её между кадрами, измеряет поток, строит кривую блеска и классифицирует тип переменности Random Forest. Обучаемая модель получает признаки извлечённой кривой; обнаружение источников и фотометрия алгоритмические. Не называть это нейросетевым распознаванием изображений.

Основная цепочка: FITS → контроль качества → обнаружение → выбор и сопровождение источника → фотометрия → кривая → признаки → Random Forest → отчёт.

Не подменять измерения искусственными кривыми и не выводить правдоподобные фиктивные вероятности. Без подходящей обученной модели доступны изображения, фотометрия и экспорт, но классификация недоступна с понятным объяснением.

Сначала реализовать TESS TESScut/TPF. Универсальный импорт произвольных FITS и наземная калибровка bias/dark/flat — отдельное расширение. Результат не является подтверждением физического типа объекта.

### Архитектурное решение и правила зависимостей

Использовать модульный монолит с вычислительным конвейером и принципами Clean Architecture. Это не полный DDD: применять предметный язык и явные инварианты, но не вводить агрегаты, CQRS, шину событий, микросервисы и репозитории для каждого dataclass. Папки создавать по мере появления кода, а не ради пустого каркаса.

Разрешённые зависимости:

```text
presentation → application → core
infrastructure → application.ports + core
bootstrap → конкретные адаптеры + application + presentation
core → стандартная библиотека + NumPy
```

- **core** определяет предметные структуры, инварианты и чистые научные операции: нормирование потока, допустимость измерения, версионированную схему признаков, принятие/отказ результата. В нём нет файлового I/O, Qt, сетевых запросов, joblib и импорта infrastructure. NumPy разрешён осознанно; доступность SciPy/Astropy/Photutils не должна требоваться для импорта domain-структур.
- **application** реализует пользовательские сценарии, их последовательность, параметры, отмену, прогресс и согласование результатов. Не строит виджеты и не открывает файлы напрямую. Здесь находятся контракты внешних операций, необходимые сценариям; использовать typing.Protocol и явную передачу зависимостей через конструктор/аргументы без DI-фреймворка.
- **infrastructure** реализует эти контракты через библиотеки и файловую систему. Адаптер отвечает за перевод внешнего формата в структуры core, единицы и обработку технических ошибок. Научные реализации не должны становиться тривиальными обёртками над каждой функцией библиотеки: один адаптер на содержательную возможность.
- **presentation** переводит действия пользователя в команды application и отображает результаты. GUI workers только запускают сценарии и передают события через Qt signals. CLI обеспечивает ту же функциональность без Qt.
- **bootstrap** — единственное место выбора конкретных реализаций и сборки приложения. Нельзя получать зависимости через глобальные singleton/service locator. GUI-импорты ленивые, headless-команды запускаются без GUI extra.

Минимальные порты по реальной необходимости: SeriesReader/FrameSource, SourceDetector, PhotometryEngine, FeatureExtractor, ModelTrainer/ModelPredictor, ArtifactStore, ReportWriter. Не создавать отдельный интерфейс для каждой математической операции. Порт кадра позволяет потоковое чтение; FITS handle принадлежит адаптеру и закрывается при завершении/отмене. Core содержит метаданные серии, а доступ к кадрам передаётся отдельным контрактом. Контракт модели возвращает числовые оценки в явном порядке классов, а итоговый статус определяют правила core.

Схема вычисления признаков и её реестр принадлежат core/classification; orchestration извлечения принадлежит application, реализации FFT/Lomb–Scargle — infrastructure/scientific. Сборка sklearn Pipeline, обучение и сериализация — адаптеры infrastructure. Ни GUI, ни core не обращаются к sklearn estimator напрямую. В core не переносить крупные массивы через многократную сериализацию: использовать NumPy и явные правила владения/неизменяемости данных.

Структуры ObservationSeries, DetectedSource и quality размещать в core/observations; ApertureConfig, Measurement, LightCurve — в core/photometry; FeatureSchema, FeatureVector, Prediction — в core/classification. Общую папку utils/shared не создавать без конкретной общей ответственности. Ошибки предметной пригодности отличаются от ошибок чтения и технических сбоев; application приводит их к понятным статусам, presentation выбирает способ отображения.

Граница модулей не требует межпроцессного общения. Модули core могут использовать узкие типы соседнего модуля в одном направлении: observations → photometry → classification в порядке передачи данных; фактические импорты направлены к более ранним типам, без циклов. Связь полного конвейера остаётся в application. Не передавать Qt objects, pandas DataFrame, Astropy HDU или sklearn estimator как публичные результаты сценариев.

Синтетические генераторы для проверки держать в tests/support; отдельный пользовательский synthetic_demo реализовать как инструмент scripts, использующий core. Не смешивать генератор изображений с рабочей фотометрией. Изменения пакетов не должны менять provenance и математический смысл вычислений.

## 4. Контракты ядра

Использовать типизированные dataclasses: ObservationSeries (идентификатор, источник, time/time_scale/time_reference, flux unit, metadata; кадры и внешние WCS-объекты доступны через адаптер, а не хранятся как открытые HDU в core); DetectedSource (id, x/y, при наличии sky coordinates, диагностические признаки); ApertureConfig; LightCurve (time, flux, flux_err, normalized_flux, relative_mag, masks/reasons, provenance); FeatureVector (schema_version, names, values, units); Prediction (model_id, scores, decision/status, reasons).

Соглашение координат: массив [row, column], отображение x=column/y=row; все преобразования WCS тестировать. Поток, относительный поток и звёздная величина — разные типы величин. Внутри сохранять точное время, на графике можно показывать дни от начала. Не терять BJD reference и систему времени.

GUI и CLI вызывают одни сценарии application; application зависит от core и собственных портов, но не от конкретной инфраструктуры. Ядро не импортирует Qt. Длительная работа через workers с сигналами и отменой между пакетами кадров; изменение виджетов только в GUI-потоке. Запретить гонку результатов после открытия другой серии, использовать run_id. Логи в файл, понятные ошибки пользователю, полный traceback в журнале. Никаких except Exception: continue без учёта и объяснения исключённых данных.

## 5. Импорт и измерение

1. Проверить FITS-структуру и тип продукта. Для TESScut/TPF читать TIME, FLUX, FLUX_ERR, QUALITY и WCS из корректных HDU/табличных ключей, а не предполагать ImageHDU. FITS может содержать весь куб в таблице. Проверять размерности, единицы, идентификаторы, сортировку времени и пропуски. Не применять TESS-адаптер к неизвестному файлу.
2. Обрабатывать кадры пакетами, не дублировать полный куб в памяти. Отдельно поддержать набор совместимых TESS-файлов. Разные камеры/секторы первоначально обрабатывать отдельно; не склеивать автоматически шкалы потоков.
3. Маскировать кадры по настраиваемой TESS quality bitmask и невалидным данным; хранить причины исключения. QUALITY=0 можно использовать как консервативный стартовый режим, но объяснять потерю данных. Нулевые ошибки и NaN проверять явно.
4. Получить опорный кадр из выборки пригодных изображений. Оценить фон/шум с маской источников; на малом cutout использовать устойчивую локальную оценку вместо Background2D с неподходящими размерами сетки.
5. Найти кандидатов DAOStarFinder после удаления фона. Порог задаётся через шум, параметры PSF/FWHM конфигурируемые. Автовыбор цели по WCS и координатам, не по самой яркой точке. При неоднозначности попросить выбрать источник в GUI. При отсутствии детекции разрешить ручную апертуру с предупреждением.
6. Сопровождать выбранный объект по WCS/смещению и ограниченному уточнению центроида. Ограничить максимальный сдвиг; потеря цели исключает кадр, а не переключает на соседа. Сохранять x/y по времени. Для TESS не выдумывать независимую WCS каждого кадра: учитывать доступные correction columns и оценку смещения.
7. Начать с фиксированной формы апертуры и контролируемого движения центра. Фон из кольца с исключением соседей и дефектов; учитывать реальные веса частичных пикселей и площадь маски. FLUX может уже иметь инструментальную коррекцию фона: прочитать документацию продукта и не вычитать её дважды; локальный остаточный фон оценивать явно.
8. Поток F=sum(w_i*pixel_i)-B*sum(w_i). Ошибка учитывает sum(w_i²*sigma_i²) и неопределённость оценки B. При отсутствии error-array использовать документированную модель ошибки либо пометить ошибку неизвестной; не выдавать ноль за точность.
9. Проверять насыщение, соседей, пересечение края, недостаточный фон, нестабильность центроида. Для наших ярких целей 15×15 может не хватить: статус «нужна большая вырезка» и возможность загрузить другую. Не обещать восстановление насыщенных звёзд простой круговой апертурой.
10. Нормировать пригодный положительный поток на медиану. Относительная величина -2.5 log10(F/Fref); ошибка через производную. При F<=0 сохранять flux и флаг, не вычислять log и не выдумывать mag. Не очищать реальные затмения глобальным 3σ. Не удалять тренд по умолчанию — можно уничтожить длиннопериодическую вариацию.

Экспортировать raw и selected измерения, маски, фон, центроиды и настройки. Уверенность классификатора не является основанием автоматически менять фотометрию: это создаёт подгонку под ответ.

## 6. Признаки, модель и датасет

Сохранить legacy_fft23 для сопоставления с ЛР2, но явно указать ограничения интерполяции через разрывы. Новая схема time_series_v2: робастный разброс и амплитуда, асимметрия, куртозис с определённой конвенцией, нормированные характеристики формы; периоды/пики Lomb–Scargle с учётом ошибок, отношения гармоник, качество периодического описания; ACF только там, где корректна временная сетка. Список, единицы и порядок признаков хранить в одном реестре. Число новых признаков определить после реализации, не называть автоматически 23. Не использовать абсолютное среднее mag для относительной фотометрии. Частотный диапазон ограничивать базой наблюдений, экспозицией и cadence; учитывать неоднозначность P/2 у затменных систем. БПФ оставить в отчёте и сравнительных экспериментах; новый метод требует обновления ЛР2.

Основная модель RandomForestClassifier(n_estimators=300, class_weight='balanced', random_state=seed). Сравнение с DummyClassifier и одним простым baseline, например StandardScaler+KNN. Преобразования/импутация обучаются только на train в Pipeline. Не использовать имя файла, каталоговый период, метку, координаты и id как скрытые признаки класса.

Стратегия данных: получать метки из документированного каталога, а обучающие кривые извлекать тем же модулем из реальных TESS серий. Каталоговые кривые — для независимой проверки фотометрии. OGLE можно использовать как отдельный эксперимент переноса, не смешивать молча с TESS. Скрипт получения данных должен иметь dry-run, оценку объёма, лимит загрузки, retries/backoff, возобновление, SHA-256 и provenance. Текущая инструкция не разрешает неограниченную массовую загрузку.

Пилот: 20–30 разных звёзд на класс для проверки покрытия и измерений, затем целевой набор порядка 200–500 на доступный класс, если качество и объём позволяют. Это ориентиры, не доказательство достаточности. Список классов фиксируется после аудита реальных данных. Начать с RR Лиры, цефеид, затменных двойных при наличии пригодных серий. Mira требует длинной базы, solar_like — подходящей чувствительности и cadence; не обещать шесть рабочих классов только ради таблицы отчёта. Неподдержанные классы обозначать явно; расширение — отдельный этап.

Разбиение по физическим объектам до обучения: все сектора, дубликаты, вырезки и аугментации звезды в одной группе. Канонический object_id через crossmatch с документированной неоднозначностью. Разделить train/validation/test, сохранить manifest разбиения; подбор и порог только на train/validation, test не трогать до финала. По возможности дополнительный контроль по сектору. При малом количестве объектов использовать grouped CV и явно указать ограничения.

Оценка: accuracy, macro-F1, precision/recall/F1/support по классам, confusion matrix, разброс по folds, устойчивость к шуму/пропускам, фотометрическая пригодность и доля отказов. Требования ЛР2 Accuracy>=0.90/Macro-F1>=0.88 — цели, не гарантии; при недостижении публиковать фактические значения. Отдельно качество на всех объектах и на принятых, чтобы отказы не скрывали ошибки.

max(predict_proba) — оценка модели, не доказанная вероятность правильности. Порог 0.70 из отчёта показать как предварительный; валидировать/калибровать на данных без утечки. Возвращать «Недостаточно данных» при провале QC и «Неуверенная классификация» при слабом результате; отказ не гарантирует обнаружения неизвестного типа. MDI показывать только как глобальную важность; permutation importance на validation — дополнительная проверка.

Артефакт модели: pipeline.joblib, metadata.json (versions, classes, feature_schema, photometry_config_hash, dataset/split hashes, metrics, seed, provenance). Не загружать непроверенные joblib-файлы пользователя; формат может исполнять код. Несовместимая схема блокирует inference с объяснением. Синтетическая модель имеет заметную метку «Демонстрационная».

## 7. GUI: спокойный минималистичный desktop

Русский интерфейс, код на английском. Основной размер 1200×800, рабочий минимум 960×640; масштабирование и HiDPI, отсутствие жёстких фиксированных размеров панелей. Qt Widgets с единым набором токенов: фон #F6F7F9, белые поверхности, основной текст #17212B, вторичный #556170, акцент #3157D5, границы #DDE2E8. Сетка 8 px, отступы 16–24, скругление 8, системный шрифт 13–14 pt, заголовок 20–24. Цвета проверить на контраст, статус всегда продублирован текстом/значком. Без стеклянных эффектов, градиентов, декоративных звёздных фонов, обилия карточек и скрытых hover-only действий.

Главное меню: Файл / Анализ / Вид / Справка, нативные диалоги и привычные Cmd/Ctrl+O, Cmd/Ctrl+S. Верхняя строка: название серии, «Открыть», «Экспорт». Левая компактная панель серий и состояния; центральная область из двух изменяемых панелей — изображение сверху/слева, график снизу/справа; правая панель выбранной звезды и результата шириной около 280 px, может сворачиваться. На узком окне изображение и графики переключаются вкладками.

Основные шаги без принудительного мастера: «1. Снимки → 2. Звезда → 3. Анализ → 4. Результат». Одна основная кнопка по состоянию. Импорт через кнопку и drag-and-drop. Пустой экран с коротким объяснением и «Открыть FITS»/«Открыть пример», никаких случайных демонстрационных графиков.

Изображение: grayscale, robust/asinh stretch только для отображения; никогда не применять визуальное растяжение к измерениям. Контуры источников и выбранной апертуры, фоновое кольцо, zoom/pan/reset, ползунок кадра и время, включаемое воспроизведение с ограниченной частотой. Выбор кликом и доступный список объектов для клавиатуры. Не соединять выбор кадра с повторным полным анализом.

Графики: вкладки «Кривая блеска», «Периодограмма», «Фаза» (если период пригоден). Подписи осей с единицами, инвертированная ось только для величин mag, исключённые точки отличаются символом. Клик по точке выбирает кадр. Отдельный переключатель flux/relative flux/relative mag, без смешения шкал.

Панель результата: предполагаемый класс, статус качества и оценка модели; компактные горизонтальные вероятности поддерживаемых классов, число использованных кадров, база наблюдений. «Подробнее» раскрывает признаки и диагностику. Параметры апертуры и пороги — в сворачиваемых «Настройках измерений»; методы ML не загромождают основной сценарий.

Обучение вынести в отдельное окно «Модель и обучение»: manifest, классы, split, параметры, запуск/отмена, метрики, экспорт артефакта. Не запускать обучение автоматически при загрузке FITS.

Состояния: empty/loading/ready/selecting/extracting/analyzing/complete/cancelled/error. Прогресс с этапом и реальным счётчиком, без выдуманных процентов/ETA. Отмена сохраняет исходные данные, неполный результат явно помечен. Ошибка содержит действие: выбрать другой файл, изменить апертуру, открыть журнал. Несохранённая сессия требует подтверждения при закрытии. Клавиатурная навигация, видимый focus, accessible names, предсказуемый Tab-order, никаких обязательных анимаций.

Сессия — версионированный JSON с путями/хэшами, выбранной целью, настройками и ссылками на результаты; большие кадры не дублируются. При перемещении данных предложить найти файл. Сохранение атомарное. Экспорт: CSV кривой, JSON результата, PNG графиков, автономный HTML-отчёт с источником, параметрами, качеством и моделью. Основной анализ работает офлайн на локальных данных.

## 8. Проверка и критерии приёмки

Фотометрия: детерминированные искусственные изображения с известной PSF, потоком, фоном, шумом, дрейфом, соседями и затмениями. Проверить восстановление потока в пределах ожидаемой ошибки, сохранение глубины затмения, отсутствие перескока цели, корректные NaN/края/отмена. На реальных данных сравнить нормированную извлечённую кривую с независимой архивной кривой того же объекта/сектора; учитывать различие апертур и detrending, сохранять остатки и метрики. Не объявлять качество по одному красивому графику.

FITS: настоящий компактный fixture с TIME/FLUX/ERROR/QUALITY/WCS, неправильный продукт, отсутствующие колонки, ошибки времени и размерности. Модели: отсутствие утечки object_id, повторяемость split, несовместимая схема, отсутствие модели и слабый результат. Архитектура: автоматически проверять запреты импортов между слоями, отсутствие циклов, независимость core от Qt/Astropy/sklearn и запуск CLI без GUI extra. Сценарии тестировать с маленькими fake-адаптерами, реальные FITS/Photutils/sklearn адаптеры — интеграционно. GUI: загрузка→выбор→измерение→экспорт, ошибка, отмена, повторный запуск; event loop остаётся отзывчивым. Интеграционный smoke на четырёх локальных сериях может закончиться корректным QC-отказом, а не обязательно классом.

Производительность измерить на машине и записать аппаратные условия, время и peak memory; не заявлять прежние 1.28 с для нового конвейера. Полная обработка не должна блокировать окно. Большие данные не должны загружаться многократно.

Готово, когда: чистая установка запускает CLI/GUI; пользователь получает измеренную кривую из FITS без ручного CSV; апертура и исключения видны; результаты воспроизводимы; при наличии валидированной модели есть класс/отказ; нет модели — нет фиктивного класса; тесты/ruff проходят; README описывает все ограничения, источники и реальные метрики. Финальная готовность классификации требует реального размеченного датасета и валидации, одного GUI недостаточно.
